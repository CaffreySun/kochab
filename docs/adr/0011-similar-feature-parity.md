# 0011 相似功能逐项对标：保留我们的，吸收对方的

- 状态：已采纳
- 日期：2026-10-17
- 关联：[ADR 0010](0010-linkandroid-inspired-device-tools.md)（新增能力）

## 背景

0010 解决的是「LinkAndroid 有、我们没有」的功能。本 ADR 换一个角度：
对**两边都有的功能**逐个读实现、比较差异，明确哪些是对方更优、可以直接吸收，
哪些是我们更优、继续保留。判断标准不是「谁功能多」，而是：

1. 用户是否更容易完成任务；
2. 失败路径是否诚实（不谎报成功、不丢错误）；
3. 是否与现有架构（独立窗口、Rust 领域层、任务队列）冲突。

调研对象：`modstart-lib/linkandroid@main` 的
`src/pages/Device`、`src/store/modules/device.ts`、`electron/mapi/{adb,file,app,scrcpy}`。
只读代码，不复制实现；大模型相关模块不在范围内。

## 逐项对比

| 功能 | LinkAndroid 的做法 | 本项目现状 | 判断 | 处置 |
| --- | --- | --- | --- | --- |
| 设备发现 | 常驻 DeviceManage 子进程 + WebSocket + adb watch，前端重连 | Rust 侧 `track-devices` 推送，缓存详情 | 我们的链路更短，无需子进程 | 保留 |
| 设备卡片 | 整卡点击选中、可改设备名、可置顶、USB/WiFi 图标 | 复选框选中、缩略图、操作栏、分组、状态；显示序列号 | 对方别名/置顶更好；我们的预览与操作栏更强 | **吸收别名、置顶、全选** |
| 分组 | 一台设备可属于多个分组 | 单分组 + 分组筛选/排序 | 多分组更灵活，但会改存储模型与全部筛选逻辑 | 暂不吸收，记录为后续 |
| 无线连接 | tcpip + 连接、断网口、二维码/配对码配对 | 已支持 tcpip + 自动连接、切回 USB | 配对是对方强项，但需要 TLS/SPAKE2，测试机 Android 10 无法验证 | 0010 已记录为后续 |
| 投屏实现 | 拉起 scrcpy 可执行文件，独立窗口 | 自研协议，画面嵌入窗口，窗口随方向/面板重排 | 我们的窗口一体化与面板布局更贴合本项目 | 保留 |
| 投屏参数 | 码率/FPS、置顶、无边框、自动投屏、关屏、声音、自定义参数 | 分辨率上限、FPS、码率、触摸点、常亮；按窗口共享 | 对方部分参数依赖外部 scrcpy 窗口；我们缺「置顶/无边框」 | 保留现有；置顶等记录为后续 |
| 截屏 | `screencap` → base64 → 图片美化页 | 0010：直接落盘「下载」 | 我们的结果可复用、可归档 | 保留 |
| 录屏 | `screenrecord`，可转 GIF；停止靠杀 adb 进程 | 0010：MP4，SIGINT 收尾，自动保存 | 我们的停止方式更可靠；GIF 依赖 ffmpeg | 保留；GIF 不做 |
| 应用列表 | 名称/包名搜索，图标走外部 iconx 服务 | 设备侧 label + 包名搜索，系统/第三方区分，更多操作 | 我们信息更全；图标服务引入外部依赖，不采纳 | 保留 |
| 应用安装 | 文件选择 → 安装 | 文件选择 + 失败原因 + 降级安装参数 | 我们更完整 | 保留 |
| 卸载/清数据 | 卸载前确认；清数据无单独确认 | **直接执行** | 对方在破坏性操作上更谨慎 | **吸收：两者都加确认** |
| 应用导出 | 无 | base + split 全部导出，自动命名/子目录 | 我们更强 | 保留 |
| 文件浏览 | 弹窗、可编辑路径、排序、刷新、列表/网格 | 设备窗口面板、面包屑、快捷路径、表格 | 对方路径编辑/排序/刷新更好；我们的布局与快捷路径更好 | **吸收路径编辑、排序、刷新** |
| 文件上传 | 单文件 | 单文件 | 差异不大 | **顺手改为多文件** |
| 文件下载 | 多选；目录递归下载 | 单文件，每次弹目录 | 对方批量与目录下载明显更好 | **吸收：多选、批量、目录递归** |
| 文件删除 | 多选 + 确认 | 单条、直接删 | 对方更安全、更高效 | **吸收：多选 + 二次确认** |
| 重命名/新建目录 | 无重命名；有新建 | 后端有重命名，UI 未暴露 | 我们后端已有能力，补 UI 即可 | **暴露重命名** |
| 命令行 | 终端式，支持长命令流式输出、历史 | 一次性命令 + 退出码 + 超时，无历史 | 对方历史与长命令更好；我们退出码/超时更严谨 | **吸收历史与快捷命令**；流式输出记录为后续 |
| 设备信息 | 卡片状态点；信息有限 | 概览页（电量/存储/内存/网络/系统） | 我们更强 | 保留 |
| 批量任务 | 批量安装/投屏/连接，只有 toast | 任务队列，逐台结果持久化 | 我们的结果可追溯 | 保留 |
| 窗口交互 | 独立 scrcpy 窗口 | 独立窗口 + 面板 + 方向重排 + 会话优先级 | 我们更强 | 保留 |

## 本轮吸收的具体改动

### 1. 文件管理

后端 `android-core::file::pull_dir`：

- 一个 sync 会话内递归遍历，空目录保留；
- 符号链接不跟随（避免环与越界）；
- 层级上限 32；
- 设备文件名按 Windows 规则清洗（`:`/`?`/`*` 等替换，`CON` 等保留名加前缀）；
- 返回实际落盘目录与总字节数。

命令与前端：

- 新命令 `file_pull_dir`（目标为父目录，由后端决定最终目录名）；
- 文件页新增行选择、批量下载、批量删除、编辑路径、排序（名称/时间/大小）、刷新；
- 删除改为确认弹窗；上传支持多选；补上重命名入口。

### 2. 设备列表

- 工具栏新增「全选 / 取消全选」，只作用于当前可见的就绪设备；
- 设备偏好持久化在 `ac.devicePrefs`：自定义名称与置顶顺序；
- 卡片优先显示自定义名称，序列号保留在 tooltip；搜索同时匹配别名；
- 「更多」菜单新增重命名与置顶/取消置顶。

### 3. 命令行

- 常用命令按钮：电池、分辨率、密度、前台窗口、Wi-Fi 地址、第三方应用；
- 最近命令持久化在 `ac.shellHistory`（去重、最多 20 条），点击回填；
- 保留我们原有的退出码展示与超时，不改成看不到结果的纯终端。

### 4. 应用管理

- 卸载、清除数据都先弹确认，确认后才调用命令；
- 启动/停止/安装/导出的行为不变。

## 明确不吸收的项

| 项 | 原因 |
| --- | --- |
| 外部应用图标服务 | 引入网络依赖与隐私边界，图标加载失败还会闪空 |
| 自动投屏 | 设备插入即弹窗，对批量管理场景是干扰 |
| 多分组 | 需要迁移 `ac.deviceGroups` 结构并重写筛选/任务作用域，收益与风险不匹配 |
| 终端流式输出 | 需要新的后端会话 + 事件协议；本轮先补历史与快捷命令 |
| 文件传输进度条 | 需要改造 sync 层回调并新增事件；当前以忙碌态 + 结果提示覆盖 |
| GIF 录屏 | 需要随包分发或要求用户安装 ffmpeg |
| Android 11 配对/虚拟屏投屏 | 见 0010 的触发条件 |

## 验证

真机：Xiaomi MIX 2S（Android 10 / API 29）。

| 项 | 结果 |
| --- | --- |
| 递归下载目录 | `/sdcard/Download/ac_e2e_*`（含 `a.txt`、`sub/b.txt`）在文件页选中 → 下载到自定义目录；本地结构一致，内容分别为 `alpha` / `beta` |
| 批量选择 | 选中 1 行后「下载所选（1）」「删除所选（1）」从禁用变为可用；选 2 行后计数同步为 2 |
| 删除确认 | 删除目录弹出「将删除 1 项：ac_e2e_… 目录会连同内容一起删除」，取消后设备文件仍在 |
| 路径编辑 | 编辑路径输入 `/sdcard/Download` 回车后列表切换到 Download |
| 全选 | 工具栏「全选」后按钮变为「取消全选」，选中数变为 1 |
| 设备别名 | 重命名为「小明的 MIX 2S」后卡片立即显示；清空保存后恢复序列号 |
| 命令行快捷命令 | 点「电池」填入 `dumpsys battery`，执行后退出码 0、输出完整电量信息，出现在「最近」 |
| 卸载确认 | 第三方应用点「卸载」弹出「将卸载「com.bb.happykids」，应用数据会被一并删除」，取消后设备未变化 |

自动化：

- `cargo test`：递归下载真机用例通过（创建目录/子目录/两个文件 → 下载 → 比对结构与内容 → 清理）；
- Vitest：批量下载、删除确认、路径编辑、全选、别名、置顶、快捷命令、卸载确认；
- `pnpm verify:fast`：10/10 通过。
