# 0009 独立设备窗口与会话优先级

- 状态：已采纳
- 日期：2026-10-16

## 背景

设备卡片上的四个入口（投屏 / 应用 / 文件 / 更多）最初都在主窗口内部切换路由。
但设备列表页本身还要承担「多设备缩略图」，两个诉求挤在一个窗口里互相打架：

- 缩略图需要一直活着，才能一眼看出哪台设备在线；
- 投屏需要全屏、需要独立焦点，多个设备同时看时窗口太小就没法用。

另外发现一个更硬的问题：**scrcpy 的 SPS/PPS 只在会话建立时下发一次**。

## 决策

### 1. 每台设备一个独立窗口

用同一个前端产物 + 查询串区分形态：

```
主窗口      index.html
设备窗口    index.html?window=device&serial=<serial>&panel=<apps|files|overview>&mirror=<0|1>
```

窗口内部是「**投屏常驻左栏 + 右栏切换 应用 / 文件 / 概览**」：

- 投屏是这台设备唯一持续变化的信息，所以它不参与标签切换，也不该被切走时卸载
  （卸载 = 停会话再重建，而 SPS/PPS 只在建连时下发，重建期间画面是黑的）。
- 右栏吃剩余宽度，可拖拽分隔条调整比例；两侧都有最小宽度，窗口也有对应的 minWidth。
- `panel` / `mirror` 只是**初始值**，之后由用户操作或主窗口的入口意图更新。

窗口标签是 `device-<serial>`：一台设备只占一个窗口。主窗口再点这台设备的其它入口时，
聚焦已有窗口并发一个 `device://entry-request` 事件，而不是再开一个窗口。

入口意图的语义（见 `windowMode.ts` 的 `entryIntent`）：

| 卡片入口 | 自动开始投屏 | 右栏 |
| --- | --- | --- |
| 投屏 | 是 | 不动（沿用当前） |
| 应用 | 否 | 应用 |
| 文件 | 否 | 文件 |

「投屏」只表达「我要投屏」，不抢右栏；「应用/文件」只定位右栏，**不**替用户建立会话——
只想翻文件的人不该被占掉一条设备会话，那时投屏区显示「开始投屏」由用户自己决定。

不重建视图也有硬理由：投屏会话是有状态的，重建窗口会把正在跑的会话打断。

Rust 侧 `parseWindowRoute` 是纯函数，浏览器里也能用同一套查询串调试。

### 2. 同一台设备只有一条会话，且按优先级抢占

设备端 abstract socket 是独占的，所以缩略图和投屏窗口必然争抢同一台设备。
`session_start` 的判定规则：

| 情况 | 行为 |
| --- | --- |
| 同一个 `owner` 重复启动 | 幂等复用（React 严格模式下 effect 会跑两次） |
| 新 `owner` 优先级 **≥** 当前占用者 | 接管，旧会话退位 |
| 新 `owner` 优先级 **<** 当前占用者 | 拒绝，返回 `device_busy` |

优先级常量：`PREVIEW_PRIORITY = 0`、`MIRROR_PRIORITY = 10`。

### 3. 为什么不能「复用已有会话」

最初的实现是：设备已有会话就直接把它的 `SessionInfo` 返回给新调用方。
这在单窗口下看起来没问题，一旦多窗口就必然出错：

1. **参数串档**——投屏窗口拿到的是缩略图那一档 `240x480 / 5fps`；
2. **永远黑屏**——新窗口错过会话建立时的 config 包，
   `VideoStreamDecoder` 的 `configured` 永远是 `false`，
   所有帧都在 `push()` 里被丢掉，且不报错。

第 2 点尤其隐蔽：界面显示「投屏中」，但画面全黑，没有任何错误提示。
`decoder.ts` 里那句「后续关键帧会重新同步」的注释是错的——
scrcpy 的关键帧不携带 SPS/PPS。

### 4. 优先级必须是单向的

只做「换一个 owner 就接管」还不够：缩略图重新挂载时会把投屏窗口顶掉，
两边来回抢，用户看到的是两边交替黑屏。
所以低优先级请求**不允许**抢高优先级会话，抢占必须是单向的。

## 结果

- 主窗口：设备列表 + 最多 4 路实时缩略图，被占用时显示「投屏占用中」；
- 每台设备一个独立窗口：左栏投屏常驻，右栏在应用 / 文件 / 概览之间切换；
- 进窗口是否自动投屏由入口决定（卡片点「投屏」才自动开始）；
- 投屏窗口内始终显示设备型号与序列号（没有左侧列表兜底，必须自报家门）。

## 修订

- 2026-10-16：最初是「每个标签各开一个窗口」`device-<serial>-<tab>`。
  实际使用后改为「一台设备一个窗口」，见 §1。
- 2026-10-16：窗口内一度是「投屏/应用/文件」三个平级标签，切到应用或文件时投屏整块消失。
  改为投屏常驻左栏 + 右栏标签页，并新增「概览」。

## 备选方案

- **Rust 侧缓存最后一个 config 包并重放给后来者**：需要新增命令与事件，
  且各窗口之间仍要同步解码器状态，复杂度更高。
- **解码器从关键帧里就地提取 SPS/PPS**：Android 的 MediaCodec 不保证在
  关键帧里重复参数集，不可靠。
- **放弃缩略图**：直接违背「一眼看出哪台设备在线」的产品目标。
